Case study

Real-time Chat

The web chat buyers and owners use to talk about listings, built on WebSockets. I was its main frontend contributor.

  • React
  • Redux
  • Socket.IO
  • GraphQL
Role
Frontend Engineer · main contributor
Timeline
2020 – 2026
Platform
Web · React · WebSockets

Context & role

What I owned.

Buyers message owners and agents about a listing straight from the website. I extended and maintained the chat client for six years, working with the backend engineers who ran the socket service.

What I owned

  • Threads with infinite scroll and grouped messages
  • Images, audio, video, attachments and clickable links
  • Listing links and safety notes inside conversations
  • Moving login to the website's shared session, for requests and the socket
  • The mobile layout, including on-screen keyboard fixes

Approach

What kept it reliable at scale.

  • Smooth long threads

    Paged loading with infinite scroll, and fetching only new messages instead of reloading the thread.

  • One session

    The chat uses the same session as the website, including the socket connection, so users sign in once.

  • Safer conversations

    Safety notes, banned-user handling and clear messages when sending too fast.
